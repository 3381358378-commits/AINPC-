🏯 AINPC 智能伴游系统 —— 历史文化景区多模态沉浸式导览
📖 项目简介
本项目是一个专为“资金受限、技术薄弱”的长尾历史文化景区（以 2230 年历史的龙川佗城为样板）打造的轻量级、沉浸式 AI 导览系统。
有别于传统的“机械式语音播报”或“生硬的大模型 API 套壳”，本项目依托微信小程序，采用“状态机 + 多模态大模型 + 梯级缓存”架构，彻底解决了通用大模型在文旅场景下“容易出戏、音字不同步、高并发卡顿”的三大工程痛点。

✨ 核心特性
🎭 多模态感知与状态机剧情引擎

突破单一对话局限，引入视觉大模型结合环境判定，实现“拍古井得专属解读”。

告别散点对话，硬编码状态机调度“百岁街认亲 → 越王庙答题 → 考棚殿试批改”的线性沉浸式剧本。

⏱️ 双门闩音字同步机制

底层监听音频 onTimeUpdate 动态驱动界面打字机特效。

强制“文字渲染完成”与“语音播放完成”双条件锁，确保视听严丝合缝，彻底告别“声画脱节”。

⚡ 轻量级 TTS 代理与高并发保护

后端基于 Python Flask 构建轻量化 TTS 代理，内置 LRU 内存 + MD5 磁盘 + 云端实时 三级漏斗缓存。

引入互斥锁（Mutex）与并发读写隔离，应对节假日海量游客突发请求，实测 API 成本有效压降。

🛡️ 极端移动环境韧性防护

全面采用 SafeStorage 纯内存对象接管状态，规避低版本小程序原生存储报错。

多达 7 重防闪退保护，严格规范异步渲染校验与音频组件的“置空→停止→延迟→销毁”生命周期。

🚀 快速开始（二次开发必看）
为保证项目开源脱敏与本地运行安全，克隆本仓库后，请务必完成以下三步配置方可正常运行：

1. 替换大模型 API Key
本项目底层依赖阿里云 DashScope 提供的通义千问（文本/视觉）与 CosyVoice 模型。

请前往 阿里云百炼控制台 申请你的 API Key。

打开 pages/chat/chat.js，定位到 §1 API配置 章节。

将 YOUR_DASHSCOPE_API_KEY_HERE 占位符替换为你真实的 Key。

2. 替换小程序 AppID
打开 project.config.json 文件。

将 touristappid 占位符替换为你自己在微信公众平台申请的小程序 AppID。

3. 启动本地代理服务 (TTS Server)
确保你的电脑安装了 Python 3.8+。

在项目根目录下运行代理服务：python server.py

⚠️ 端口注意事项： 目前 map-explore.js 默认访问 5001 端口，chat.js 默认访问 5006 端口。如果你的 server.py 只挂载在一个端口，请在 JS 文件中统一修改局域网 IPv4 地址与端口号。若无需语音，可将代码中的 _ENABLE_TTS_AUDIO 设为 false。

💡 关键代码设计声明（为何“不删代码”）
在本项目中，您可能会看到一些看似“冗余”或“啰嗦”的代码，这并非疏漏，而是基于户外景区复杂场景无数次踩坑后的防御性编程：

打字机 Math.max 防回跳 + checkBothDone 双门闩： 这是应对弱网音频中断、切后台回前台等极端异常的多层保险，删减任意一层均会导致死锁。

typeof onLoadedmetadata === 'function' 判空： 微信部分基础库缺乏此 Web API，一行冗余的判断能换来 0 崩溃率。

调试面板的硬编码 wx:if="{{false}}"： 这是为了保留线上应急 Debug 抓取内存错误的能力。

保留未使用的首屏 Index 页： 为了支撑 navigateBack/reLaunch 的回退栈，并为未来的扩展预留锚点。
